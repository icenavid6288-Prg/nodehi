## بدهی فنی شناخته‌شده

مواردی که آگاهانه به تعویق افتاده‌اند و باید پیش از مقیاس‌پذیری رسیدگی شوند:

| مورد | وضعیت فعلی | راه‌حل پیشنهادی |
| --- | --- | --- |
| سبد خرید فقط محلی | `localStorage` | همگام‌سازی سرور پس از ورود |
| محدودیت نرخ درون‌فرآیندی | حافظه یک پروسه | Redis برای اجرای چندنمونه‌ای |
| ارسال رویداد بدون صف | هر تلاش در جدول رویدادها ثبت می‌شود، ولی ارسال دوباره دستی است | صف پایدار (Redis/BullMQ) با تلاش مجدد خودکار |
| مقدار حساس تنظیمات بدون رمزنگاری | بدون `SETTINGS_ENCRYPTION_KEY` متن ساده ذخیره می‌شود و پنل هشدار می‌دهد | تنظیم کلید ۳۲ بایتی در محیط تولید |
| بدون تست E2E | فقط تست واحد | Playwright روی مسیر خرید |
| تصاویر جانگهدار | گرادیان + آیکون | بارگذاری عکس واقعی روی آروان |
| لاگ خطا محلی | فقط کنسول | Sentry یا معادل آن |
| فونت از CDN خارجی | Google Fonts | میزبانی محلی فونت برای استقلال و سرعت |

آخرین مورد اهمیت عملی دارد: میزبانی فونت روی دامنه خودی، یک درخواست DNS و
اتصال خارجی را حذف می‌کند و زمان رندر متن را بهبود می‌دهد. در شرایط قطعی
دسترسی به سرویس‌های خارجی، سایت از نبود فونت آسیب نمی‌بیند.

## ترتیب پیشنهادی اجرا

```
۱. Prisma + seed            ← پایه همه چیز
۲. احراز هویت OTP           ← پیش‌نیاز پنل کاربری واقعی
۳. بررسی مالکیت رکورد        ← همراه با API Routes، نه بعد از آن
۴. درگاه پرداخت             ← هسته کسب‌وکار
۵. پنل مدیریت                ← تا زمانی که ادمین نباشد، هیچ‌چیز قابل مدیریت نیست
۶. اتوماسیون n8n            ← بهره‌وری تیم
۷. تست E2E + CI/CD          ← پایداری بلندمدت
```

نکته درباره ترتیب: پنل مدیریت پیش از اتوماسیون بیاید. اگر پنل مدیریت آماده
نباشد، هیچ‌کس نمی‌تواند محصول اضافه کند، قیمت را اصلاح کند یا سفارش را پیش
ببرد — و اتوماسیون روی داده‌ای کار می‌کند که کسی نمی‌تواند نگه‌داری کند.

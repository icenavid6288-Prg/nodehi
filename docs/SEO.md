# استراتژی سئو فروشگاه نودهی

هدف: کسب رتبه در جستجوهای «خرید + نام محصول» و «قیمت + نام محصول» که بالاترین
نیت خرید را دارند، و ساختن ترافیک ارگانیک پایدار از محتوای آموزشی.

---

## ۱. معماری اطلاعات و ساختار URL

### ساختار لاتین و خوانا

مسیرها با نامک لاتین ساخته می‌شوند تا در اشتراک‌گذاری و لینک‌سازی مشکل نداشته
باشند:

```
nodehi.ir/                                       صفحه اصلی
nodehi.ir/shop                                   فروشگاه
nodehi.ir/shop?category=refrigerator             دسته‌بندی
nodehi.ir/shop?category=refrigerator&brand=samsung
nodehi.ir/product/samsung-side-by-side-rs68-28ft صفحه محصول
nodehi.ir/blog/how-to-choose-refrigerator        مقاله
nodehi.ir/guides                                 هاب راهنمای خرید
nodehi.ir/ready-to-ship                          کالاهای موجود
nodehi.ir/loyalty                                باشگاه مشتریان
```

قواعد نامک محصول: `برند-نوع-مدل` و همه با حروف کوچک و خط تیره.
مثال: `bosch-dishwasher-sms4-13` — نه `محصول-۱۲۳`.

### کنترل محتوای تکراری

صفحات فیلترشده ترکیبی با `noIndex` علامت می‌خورند. قاعده در `src/lib/seo.ts`:

```ts
// بیش از دو فیلتر فعال = صفحه ترکیبی، بدون ارزش سئو
noIndex: countActiveFilters(filters, discountedOnly) > 2
```

منطق: `?category=refrigerator` یک صفحه معنادار است. اما
`?category=refrigerator&brand=samsung&color=سفید&energy=A%2B%2B&minPrice=50000000`
صدها نسخه با محتوای تقریباً یکسان تولید می‌کند و بودجه خزش را هدر می‌دهد.

در `robots.ts` نیز پارامترهای بی‌ارزش مسدود شده‌اند:

```
Disallow: /shop?*sort=
Disallow: /shop?*page=
Disallow: /*?utm_
Disallow: /cart · /checkout · /account · /api/
Disallow: GPTBot · CCBot        ← مصرف‌کنندگان محتوا بدون ارجاع
```

## ۲. کلمات کلیدی هدفمند

### کلمات تراکنشی (بالاترین ارزش)

ساختار: `[نیت خرید] + [نام محصول] + [ویژگی متمایزکننده]`

| الگو | نمونه | صفحه هدف |
| --- | --- | --- |
| خرید + محصول | خرید یخچال ساید بای ساید | `/shop?category=refrigerator` |
| قیمت + محصول | قیمت ماشین لباسشویی ۹ کیلویی | `/shop?category=washer` |
| محصول + مدل | قیمت یخچال سامسونگ RS68 | `/product/samsung-side-by-side-rs68-28ft` |
| محصول + ویژگی | ماشین ظرفشویی کم مصرف ۱۴ نفره | `/shop?category=dishwasher` |
| برند + دسته | تلویزیون ال‌جی OLED | `/shop?brand=lg` |
| خرید + برند | خرید لوازم خانگی بوش | `/shop?brand=bosch` |

### کلمات طولانی (Long-tail) — اولویت محتوا

رقابت کم، نیت خرید بالا. این‌ها سوژه اصلی مقالات هستند:

```
ظرفیت مناسب ماشین لباسشویی برای خانواده چهار نفره
چند BTU کولر گازی برای اتاق ۲۵ متری
تفاوت یخچال No Frost و معمولی چیست
یخچال ساید بای ساید چند سانتی‌متر فاصله از دیوار لازم دارد
ماشین ظرفشویی چند لیتر آب مصرف می‌کند
بهترین برند یخچال از نظر خدمات پس از فروش در ایران
کولر گازی اینورتر چقدر در برق صرفه‌جویی می‌کند
راهنمای انتخاب ظرفیت لباسشویی برای لحاف
```

### کلمات اطلاعاتی (جذب ترافیک بالای قیف)

```
نحوه استفاده صحیح از ماشین ظرفشویی
چرا یخچال برفک می‌زند
سرویس دوره‌ای کولر گازی هر چند وقت یک بار
افزایش عمر مفید لوازم خانگی
علت صدای زیاد ماشین لباسشویی
```

این کلمات فروش مستقیم نمی‌آورند اما اعتماد می‌سازند و کاربر را در ادامه مسیر
به صفحه محصول می‌رسانند — با لینک‌سازی داخلی هدفمند.

### توزیع کلمات کلیدی در ساختار صفحه

| بخش | محتوا | نکته سئو |
| --- | --- | --- |
| `<title>` | برند + محصول + «قیمت و خرید» | حداکثر ۶۰ نویسه، کلیدواژه در ابتدا |
| `meta description` | ویژگی‌ها + گارانتی + ارسال | ۱۵۰ تا ۱۶۰ نویسه، شامل فراخوان اقدام |
| `h1` | یک‌بار در صفحه | شامل نام کامل محصول، بدون تکرار برند |
| `h2` | بخش‌های صفحه | «مشخصات فنی»، «نظرات کاربران»، «پرسش‌های متداول» |
| بدنه | توضیح + نکات کلیدی | کلیدواژه طولانی به‌صورت طبیعی |
| `alt` تصاویر | «نام محصول — تصویر ۱» | توصیفی، نه پر از کلیدواژه |

## ۳. اسکیما مارک‌آپ پیاده‌شده

همه سازنده‌ها در `src/lib/seo.ts` و تزریق در `src/components/seo/json-ld.tsx`:

| اسکیما | محل | کارکرد در نتایج گوگل |
| --- | --- | --- |
| `Organization` | ریشه سایت | شناسنامه برند، پیوند شبکه‌های اجتماعی |
| `WebSite` + `SearchAction` | ریشه سایت | نمایش جعبه جستجو در گوگل |
| `Store` | ریشه + تماس با ما | سئوی محلی، ساعات کاری، محدوده خدمات |
| `Product` | صفحه محصول | قیمت، موجودی، برند، گارانتی، شرایط مرجوعی |
| `AggregateRating` | صفحه محصول | نمایش ستاره در نتایج |
| `Review` | صفحه محصول | نظرات واقعی زیر نتیجه گوگل |
| `FAQPage` | محصول + سوالات متداول | باز شدن پرسش‌ها در نتایج |
| `BreadcrumbList` | تمام صفحات داخلی | مسیر صفحه به‌جای URL خام |
| `Article` | مقالات | تاریخ انتشار و به‌روزرسانی |
| `ItemList` | فروشگاه + صفحه اصلی | فهرست محصولات |
| `Offer` + `WarrantyPromise` | صفحه محصول | قیمت، ارز، گارانتی با واحد ماه |

### نکته مهم درباره ارز در اسکیما

اسکیما `priceCurrency: 'IRR'` است و قیمت به **ریال** ارسال می‌شود (تومان × ۱۰)،
چون گوگل تومان را نمی‌شناسد:

```ts
priceCurrency: 'IRR',
price: product.price * 10,
```

قیمتی که به کاربر نمایش داده می‌شود تومان است، اما اسکیما باید با استاندارد
بین‌المللی هم‌خوان باشد. عدم تطابق این دو باعث هشدار در Search Console می‌شود.

### بررسی صحت اسکیما

پس از انتشار، این ابزارها را اجرا کنید:

- **Google Rich Results Test** — برای هر نوع اسکیما به‌صورت جداگانه
- **Schema Markup Validator** (validator.schema.org)
- بخش «Enhancements» در Google Search Console

## ۴. سایت‌مپ و robots

سایت‌مپ به‌صورت پویا از لایه داده ساخته می‌شود (`src/app/sitemap.ts`) و شامل
تمام محصولات، دسته‌ها و مقالات با اولویت و بازه به‌روزرسانی مناسب است:

| نوع صفحه | اولویت | بازه به‌روزرسانی |
| --- | --- | --- |
| صفحه اصلی | ۱.۰ | روزانه |
| محصول | ۰.۹ | هفتگی |
| فروشگاه | ۰.۹ | روزانه |
| دسته‌بندی | ۰.۸ | روزانه |
| کالاهای آماده ارسال | ۰.۸ | ساعتی |
| مقالات | ۰.۷ | ماهانه |
| صفحات حقوقی | ۰.۳ | سالانه |

نکته: اولویت در سایت‌مپ یک *راهنما* است نه دستور. گوگل ممکن است نادیده بگیرد.
ارزش واقعی سایت‌مپ در `lastModified` صحیح است که خزش را هدفمند می‌کند.

## ۵. سرعت و Core Web Vitals

### اقدامات انجام‌شده

| اقدام | اثر |
| --- | --- |
| Server Components پیش‌فرض | باندل صفحات محتوایی تقریباً صفر (۱۹۹ بایت) |
| SSG برای محصولات و مقالات | ۵۴ صفحه استاتیک، پاسخ فوری |
| SVG درون‌خطی برای آیکون‌ها | حذف درخواست شبکه و وابستگی |
| `Intl` داخلی برای تقویم شمسی | حدود ۴۰ کیلوبایت کمتر از کتابخانه جانبی |
| `next/image` با WebP/AVIF | تصاویر بهینه و بارگذاری تنبل |
| جانگهدار گرادیانی | بدون تصویر سنگین، بدون Layout Shift |
| فونت با `display=swap` | متون بلافاصله با فونت جایگزین دیده می‌شوند |
| هدر `immutable` برای `_next/static` | کش یک‌ساله دارایی‌ها |
| `prefers-reduced-motion` | احترام به تنظیم کاربر |

### اهداف

| شاخص | هدف | معیار |
| --- | --- | --- |
| LCP | زیر ۲.۵ ثانیه | Largest Contentful Paint |
| CLS | زیر ۰.۱ | Cumulative Layout Shift |
| INP | زیر ۲۰۰ میلی‌ثانیه | Interaction to Next Paint |
| TTFB | زیر ۸۰۰ میلی‌ثانیه | Time To First Byte |
| Lighthouse | بالای ۹۰ در هر چهار بخش | Performance / A11y / Best Practices / SEO |

### نکات مهم که رعایت شده

- **ابعاد ثابت تصاویر** با `aspect-square` تا CLS صفر بماند.
- **آیکون‌ها درون‌خطی** — نه فایل جداگانه، نه درخواست اضافه.
- **فونت فقط با وزن‌های مورد نیاز** (۳۰۰ تا ۸۰۰) نه کل خانواده.
- **بدون انیمیشن سنگین** در مسیر بحرینی رندر.

## ۶. سئوی محلی

برای فروشگاه لوازم خانگی، جستجوهای محلی نیت خرید بسیار بالایی دارند
(«تعمیرگاه یخچال سامسونگ در تهران»، «فروشگاه لوازم خانگی نزدیک من»).

### Google Business Profile

- [ ] ثبت نمادین هر شعبه به‌صورت جداگانه (تهران، اصفهان)
- [ ] دسته‌بندی اصلی: «فروشگاه لوازم خانگی»
- [ ] دسته‌بندی‌های فرعی: «فروشگاه لوازم برقی»، «تعمیرگاه لوازم خانگی»
- [ ] ساعات کاری دقیق و به‌روز (شامل تعطیلات)
- [ ] حداقل ۲۰ تصویر واقعی از فروشگاه و محصولات
- [ ] شماره تلفن محلی (نه شماره سراسری)
- [ ] پیش از تکمیل، پیام ترجیحی فعال شود تا سوالات پاسخ داده شوند
- [ ] درخواست نظر از مشتریان راضی — منظم و پیوسته
- [ ] پاسخ به تمام نظرات، حتی منفی (پاسخ حرفه‌ای اعتماد می‌سازد)

### داده ساختاریافته محلی

اسکیمای `Store` در `src/lib/seo.ts` شامل: نشانی، کد پستی، مختصات جغرافیایی،
ساعات کاری و محدوده خدمات (`areaServed`) بر اساس شعبه‌های تعریف‌شده در
`src/config/brand.ts`.

### سازگاری NAP

نام، نشانی و تلفن (NAP) باید **دقیقاً یکسان** در سایت، Google Business Profile،
ترب، دیجی‌کالا و سایر پروفایل‌ها باشد. حتی اختلاف در نوشتار «خیابان ولیعصر» و
«خ ولیعصر» می‌تواند اعتبار محلی را تضعیف کند.

## ۷. لینک‌سازی داخلی

### ساختار پیاده‌شده

```
صفحه اصلی
  ├─ دسته‌بندی‌ها (با متن سئوی اختصاصی هر دسته)
  ├─ برندها (پیوند به صفحه فیلترشده هر برند)
  ├─ محصولات پرفروش / تخفیف‌دار / آماده ارسال
  └─ مقالات شاخص
        ↓
صفحه محصول
  ├─ مسیر راهنما: خانه › دسته › برند › محصول
  ├─ محصولات مشابه (relatedProducts)
  ├─ پرسش‌های متداول اختصاصی
  └─ نظرات کاربران
        ↓
مقاله
  ├─ محصولات مرتبط با کلمات کلیدی مقاله (لینک‌سازی هدفمند)
  ├─ کلمات کلیدی قابل کلیک → هدایت به فروشگاه
  └─ مقالات مرتبط
```

### نقاط قوت این ساختار

- **هیچ صفحه یتیمی وجود ندارد.** هر محصول حداقل از سه مسیر قابل دسترسی است:
  دسته‌بندی، برند و محصولات مشابه.
- **متن لنگر توصیفی است.** «یخچال ساید بای ساید سامسونگ» به‌جای «بیشتر بخوانید».
- **مقالات به محصولات لینک می‌دهند.** ترافیک اطلاعاتی به صفحه تراکنشی هدایت می‌شود.
- **صفحه اصلی به دسته‌ها قدرت می‌دهد.** با متن سئوی اختصاصی، نه فقط فهرست لینک.

## ۸. استراتژی محتوا

نسبت پیشنهادی: **۴۰٪ محتوای تراکنشی بهینه‌شده / ۶۰٪ محتوای آموزشی**

| نوع محتوا | هدف | بازه انتشار |
| --- | --- | --- |
| راهنمای خرید دسته‌بندی | ترافیک بالا قیف | ۲ در ماه |
| مقایسه دو برند/مدل | تصمیم‌گیری خرید | ۱ در ماه |
| آموزش استفاده و نگهداری | ترافیک اطلاعاتی + اعتماد | ۲ در ماه |
| پرسش‌های متداول محصول | پاسخ به سوال واقعی مشتری | پیوسته |

### منبع محتوا — مهم‌ترین نکته

بهترین محتوای فروشگاه از **سوالات واقعی مشتریان** می‌آید. هر پرسشی که مشاوران
تلفنی روزانه پاسخ می‌دهند، یک مقاله یا بخش پرسش‌های متداول است.

به همین دلیل، پرسش‌های متداول محصول در `src/app/product/[slug]/page.tsx` به‌صورت
قالبی و اختصاصی هر محصول ساخته می‌شوند (گارانتی این کالا، ارسال این کالا، خرید
اقساطی این کالا) و هم‌زمان در اسکیمای `FAQPage` تزریق می‌شوند. نتیجه: پرسش‌های
پرکاربردی که کاربر واقعاً می‌پرسد، در نتایج گوگل باز می‌شوند.

## ۹. چک‌لیست فنی پیش از انتشار

```
مبانی
[ ] NEXT_PUBLIC_SITE_URL روی دامنه واقعی تنظیم شد
[ ] metadataBase در layout.tsx آدرس صحیح دارد
[ ] تمام صفحات title و description یکتا دارند
[ ] فقط یک h1 در هر صفحه وجود دارد
[ ] کدهای HTTP صحیح: 404 برای ناموجود، 410 برای حذف دائمی

اسکیما
[ ] Rich Results Test روی نمونه محصول، مقاله و دسته‌بندی اجرا شد
[ ] اسکیما Review فقط برای نظرات واقعی و تأییدشده استفاده شد
[ ] قیمت اسکیما با قیمت نمایشی هم‌خوان است (تومان × ۱۰ = ریال)

خزش و ایندکس
[ ] robots.txt بدون مسدودسازی ناخواسته
[ ] sitemap.xml در Search Console ثبت شد
[ ] صفحات کم‌ارزش noIndex شده‌اند
[ ] canonical در تمام صفحات تنظیم است

سرعت
[ ] Lighthouse بالای ۹۰ در هر چهار بخش
[ ] LCP زیر ۲.۵ ثانیه روی موبایل
[ ] CLS زیر ۰.۱
[ ] تصاویر در ابعاد و فرمت صحیح (WebP/AVIF)
[ ] فشرده‌سازی gzip/brotli فعال

محلی
[ ] Google Business Profile برای هر شعبه ثبت شد
[ ] کد پستی و مختصات جغرافیایی درست است
[ ] سازگاری NAP در تمام پروفایل‌ها بررسی شد

پایش
[ ] Search Console و Analytics نصب شد
[ ] Core Web Vitals گزارش‌گیری و هشدار فعال است
[ ] پایش رتبه کلمات کلیدی هدف راه‌اندازی شد
```

> **هشدار درباره `aggregateRating`:** گوگل استفاده از `Review` و
> `AggregateRating` برای نظرات غیرواقعی را به‌عنوان «داده ساختاریافته اسپم»
> تلقی می‌کند و ممکن است کل سایت را جریمه کند. این اسکیما فقط برای نظرات
> واقعی و تأییدشده کاربران استفاده شود — نه نظرات ساختگی برای بهبود ظاهر.

# معماری پروژه نودهی

---

## نمای کلی

```
┌────────────────────────────────────────────────────────────┐
│ مرورگر                                                     │
│  React 18 + Vite + React Router + Tailwind                 │
│  • سبد خرید / علاقه‌مندی → localStorage                    │
│  • توکن ورود → localStorage (Bearer)                       │
│  • فیلترها → query string در URL                           │
└───────────────────────────┬────────────────────────────────┘
                            │ HTTPS / JSON
┌───────────────────────────▼────────────────────────────────┐
│ Laravel 12 — API                                           │
│  routes/api.php → Controllers → Eloquent → SQLite          │
│  • قیمت، تخفیف و موجودی سمت سرور                           │
│  • OTP، نشست هش‌شده، محدودیت نرخ                           │
│  • کد تخفیف، سفارش، پیگیری، محتوای صفحات                   │
└───────────────────────────┬────────────────────────────────┘
                            │
                 ┌──────────▼──────────┐
                 │ SQLite (توسعه)      │
                 │ MySQL/PostgreSQL    │
                 └─────────────────────┘
```

در تولید، فرانت‌اند یک بستهٔ استاتیک است (`frontend/dist`) و API روی دامنه یا
زیردامنهٔ جدا اجرا می‌شود. مسیر عمومی وب‌سرور برای لاراول فقط `backend/public` است.

## جریان یک درخواست خرید

1. کاربر محصول را از `GET /api/products` یا صفحهٔ محصول می‌گیرد.
2. سبد در `localStorage` نگه داشته می‌شود؛ هیچ قیمتی از سبد مرجع نیست.
3. `POST /api/coupons/validate` فقط برای پیش‌نمایش تخفیف است.
4. `POST /api/checkout` نامک و تعداد را می‌گیرد و در یک تراکنش:
   - محصول را با قفل ردیف می‌خواند،
   - موجودی و قیمت را بررسی می‌کند،
   - کد تخفیف را از دیتابیس اعتبارسنجی می‌کند،
   - هزینهٔ ارسال را از تنظیمات می‌خواند،
   - سفارش و اقلام را با کپی نام/قیمت ثبت می‌کند.
5. سفارش پرداخت در محل با وضعیت `processing` و موجودی کاسته‌شده ثبت می‌شود.
   سفارش آنلاین/اقساطی `pending` می‌ماند و موجودی را قفل نمی‌کند.
6. برای سفارش آنلاین، **بعد از commit تراکنش** از درگاه authority گرفته می‌شود
   (تماس شبکه‌ای داخل تراکنش نمی‌ماند) و لینک StartPay در پاسخ برمی‌گردد.

---

## پرداخت آنلاین

```
POST /api/checkout                 → OnlinePaymentService::start()  → authority + StartPay
GET  /api/payments/zarinpal/callback → OnlinePaymentService::settle() → verify + paid
```

- `app/Services/ZarinpalGateway.php` فقط پروتکل درگاه است: endpointها، پارامترها،
  تفسیر کد ۱۰۰/۱۰۱ و خطاها، تبدیل تومان به ریال و ماسک کارت.
- `app/Services/OnlinePaymentService.php` سیاست سفارش است: مالکیت، استفادهٔ
  دوباره از authority، شرط `pending → paid`، آزادکردن authority در خطای قطعی،
  نگه‌داشتن آن در خطای ارتباطی و ثبت `audit_logs`.
- پیکربندی از ردیف `payment_gateways` (کلید `online`) خوانده می‌شود و متغیرهای
  محیطی فقط جایگزین‌اند؛ پس خاموش‌کردن درگاه در پنل، شروع پرداخت تازه را
  می‌بندد ولی تأیید تراکنش باز را نمی‌بندد.
- پس از verify موفق، کاربر با `303` به `/checkout/result` در SPA برمی‌گردد؛
  درگاه فقط `state`/`order`/`code` می‌فرستد و متن فارسی سمت کلاینت ساخته می‌شود.

## سئو و prerender

```
frontend/src/lib/seo-source.ts  → هستهٔ مشترک متا و JSON-LD (بدون DOM/React)
frontend/src/lib/seo.ts         → usePageMeta: اعمال همان متادیتا روی DOM کلاینت
scripts/prerender.mjs           → با tsx همان ماژول‌ها را import می‌کند و
                                   dist/{path}/index.html + sitemap + robots می‌سازد
src/data/prerender-targets.json → دادهٔ ورودی پررندر (کاتالوگ با seo:refresh از API)
```

- هیچ متادیتایی دو بار نوشته نمی‌شود: `productMeta(product)` هم متادیتای صفحهٔ
  تعاملی و هم عنوان/canonical/JSON-LD نسخهٔ ایستای همان مسیر است. مارک‌آپ
  سوالات و باشگاه هم از مؤلفه‌های React مشترک (`FaqAccordion`, `LoyaltyTables`)
  با `renderToStaticMarkup` رندر می‌شود.
- محتوای مقاله/سوال/حقوقی/وفاداری از seederها در targets.json می‌آید؛ فهرست
  اسلاگ‌های کاتالوگ با `npm run seo:refresh` از API زنده تازه می‌شود (build
  تکرارپذیر، بدون وابستگی به API هنگام ساخت).
- SPA همان باندل را لود می‌کند و React محتوای `#root` را جایگزین می‌کند؛
  خزنده‌های بدون JS هم محتوای واقعی و لینک‌های `<a href>` را می‌بینند.
- هر مسیر پوشه‌ای است؛ Nginx با `try_files $uri $uri/ $uri/index.html /index.html`
  سرو می‌شود و `404.html` پوستهٔ SPA برای fallback نوشته می‌شود.
- جزئیات در `docs/SEO.md` آمده است.

## احراز هویت

```
POST /api/auth/otp/request  → کد ۵ رقمی، هش SHA-256 با نمک شماره
POST /api/auth/otp/verify   → بررسی هش، ساخت نشست
Authorization: Bearer <token>
```

- توکن خام ۳۲ بایتی فقط به مرورگر برمی‌گردد؛ در جدول `auth_sessions` فقط
  `sha256(token)` ذخیره می‌شود.
- `auth.token` برای مسیرهای اجباری و `auth.optional` برای مسیرهایی است که مهمان هم
  مجاز است (تسویه، ثبت نظر، هشدار موجودی). در حالت اختیاری، سفارش مهمان به حساب
  کاربر دیگری وصل نمی‌شود.
- کد فعال قبلی با هر درخواست تازه باطل می‌شود؛ سقف ۳ درخواست در ۲ دقیقه برای هر
  شماره و سقف IP روی مسیر اعمال می‌شود.

| گروه | مدل‌ها |
| --- | --- |
| کاربر و نشست | `User`, `Address`, `OtpCode`, `AuthSession` |
| کاتالوگ | `Category`, `Brand`, `Product` |

کلید عمومی محسوب می‌شوند.

## قواعد تجاری

- منبع حقیقت هزینهٔ ارسال: تنظیمات `shipping.freeThreshold` و `shipping.cost` در
  جدول `Setting` (مقادیر اولیه ۲۰٬۰۰۰٬۰۰۰ و ۴۵۰٬۰۰۰ تومان). فرانت‌اند همین
  مقادیر را از `GET /api/settings/public` می‌خواند.
- حداقل مبلغ خرید اقساطی: ۳۰٬۰۰۰٬۰۰۰ تومان، سمت سرور.
- حداکثر ۲۰ قلم در هر سفارش و حداکثر ۲۰ عدد از هر قلم.
- تخفیف پیش از هزینهٔ ارسال اعمال می‌شود؛ آستانهٔ ارسال رایگان بر مبلغ پیش از
  تخفیف سنجیده می‌شود تا با نمایش صفحهٔ تسویه یکسان باشد.

## محتوا

محتوای صفحات عمومی از جدول‌های محتوا خوانده می‌شود و با
`backend/database/seeders/ContentSeeder.php` از
`backend/database/seeders/data/content.json` پر می‌شود. این فایل شامل ۶ مقاله،
۸ پرسش متداول، صفحات حقوقی و دادهٔ باشگاه مشتریان است. اگر seed اجرا نشود،
APIها آرایه‌های خالی برمی‌گردانند و صفحه مربوطه پیام «موردی ثبت نشده» نشان می‌دهد.

## چرا این ساختار؟

- **لاراول + React** روی هاست اشتراکی PHP قابل اجراست؛ نیازی به پروسهٔ Node در
  تولید نیست.
- **API جدا از UI** امکان استفادهٔ آیندهٔ اپ موبایل و اتوماسیون را می‌دهد.
- **SQLite در توسعه** نصب را ساده می‌کند؛ مهاجرت به MySQL/PostgreSQL فقط تغییر
  `DB_CONNECTION` و اجرای migration است.
- **قیمت سمت سرور** جلوی دستکاری قیمت در DevTools را می‌گیرد.
